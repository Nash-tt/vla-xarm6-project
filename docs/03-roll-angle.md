# 03 · roll 角度约定：一个让整维学不动的 22 倍

> 工具：`tools/trim_scan_segments.py --unwrap-roll`　相关：`pi0_ultrasound_lora/unwrap_roll.py`

## 现象

一批轨迹被做成了两份数据集，我们以为它们只是「同一个东西的两种存法」。
直到发现旧的 20k 训练结果里，**roll 这一维基本没学到东西**——
预测的 roll 几乎是一条直线，而示范数据里它在明显地变。

## 根因：360 的整数倍

两份数据集确实是**同一批轨迹**：

- 非 roll 维逐位相同
- roll 维只差 360 的整数倍，**残差严格为 0**

差别只在角度表示：

| 版本 | 约定 | roll 的实际范围 | std |
|---|---|---|---|
| `..._pi0_6d_rollunwrap` | 展开（unwrap） | `[163.967, 193.039]` | 7.77 |
| `..._smolvla_6d_no_depth` | wrap 到 ±180 | 跨 0 点分成两簇 | **172.07** |

展开版是一段连续的角度；wrap 版把它折到 `[-180, 180]`，
于是原本连续的区间在 ±180 处被剪断，变成两簇相距很远的点。

**std 从 7.77 变成 172.07，放大了 22 倍。**

## 为什么这对回归型策略是实打实的伤害

三件事同时发生：

1. **归一化尺度被放大 22 倍。** LeRobot 默认对 action 用 `MEAN_STD`，
   也就是除以 std。std 大 22 倍 → 这一维被压扁 22 倍 → 梯度尺度随之变小 →
   在和其他维共享学习率的情况下，这一维基本学不动。

2. **均值落在数据里不存在的空档。** wrap 后算出来的均值是 22.99°，
   它正好落在两簇之间的空档里——**数据中根本没有这个值**。
   归一化用这样一个均值去中心化，等于给模型一个错误的原点。

3. **相邻帧之间出现 359° 的跳变。** ep22 物理上跨过 180°，
   wrap 之后同一回合内相邻两帧的目标值相差 359°。
   对模型来说这是一次毫无理由的巨大动作。

### 量化代价

旧那次 20k run 用的是 wrap 版 + `ACTION: MEAN_STD`，代价可以算得很清楚：

| | 整个物理 roll 区间 `[163.967, 193.039]` 归一化后 |
|---|---|
| wrap 版（旧 20k） | `z ∈ [0.8193, 0.9883]`，**跨度 0.169**，且挤在 z≈+0.9 |
| 展开版（现在） | `z ∈ [−1.4424, +2.2719]`，**跨度 3.71** |

也就是说旧模型看到的 roll 目标**近似是个常数**（挤在 +0.9 附近，只占 0.169 个标准差）。
新数据集让同一个物理区间展开到 3.71 个标准差。

**结论：那个 20k 的 checkpoint 在 roll 维度上等于没训练，不要拿它当基线做对比。**

## 解决

不原地改数据（保持原数据集不动），而是**输出统一口径的副本**：

```bash
python tools/trim_scan_segments.py --src <原数据集> --dst <裁剪版> --unwrap-roll
```

`--unwrap-roll` 默认关闭。解 wrap 之后，smolvla 版的 roll 统计与 pi0 版**逐位相同**。

**已定的口径（2026-10-12）：**

- π0 训练用 `vla_batch_20261007_pi0_6d_rollunwrap_scan`（本来就是展开的）
- SmolVLA 训练用 `vla_batch_20261007_smolvla_6d_no_depth_rollunwrap_scan`（解 wrap 后）

## 一个容易写错的验证细节

比较两个版本时**必须用环绕距离**：

```python
d = (d + 180) % 360 - 180
```

直接用 `a - b` 会在跨 0 点的地方算出 **359.8° 的假偏差**，
然后你会以为两份数据不一致——而它们其实只差一个 360 的整数倍。

同理，裁剪的边界判据本身也用环绕口径，
所以 `--unwrap-roll` 这个开关**不影响裁剪结果**（切的位置一样），只影响数值表示。

## 教训

1. **同一个物理量可以有多种合法表示，而框架对表示是有假设的。**
   角度、四元数/欧拉角、坐标系，都属于这类。
   在把数据交给框架之前，先确认「框架期望的表示是什么」。
2. 22 倍这个数字说明：归一化会**放大**表示选择的影响。
   `MEAN_STD` 默认除以 std，任何让分布变宽的人为因素都会直接削弱这一维的学习。
3. 一个维度没学好，未必是模型容量或学习率的问题——
   **先去看那一维归一化之后长什么样**，比调参快得多。
