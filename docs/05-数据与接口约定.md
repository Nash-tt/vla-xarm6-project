# 数据与接口约定

本文件定义采集、训练和执行之间需要保持一致的约定。核对日期：2026-10-13。接口实现以当前代码为依据，实际机器上的部署版本仍需核对。

## 1. 位姿、动作与归一化

| 项目 | 当前定义 | 代码依据 |
|---|---|---|
| 状态 | 当前实际 TCP 六维位姿 | `align_vla_episode.py:interpolate_robot` |
| 动作标签 | 当时已下发并生效的目标 TCP 位姿 | `align_vla_episode.py:active_action` |
| 六维顺序 | `x, y, z, roll, pitch, yaw` | `remote_client.py:DIMS` 及各数据处理脚本 |
| 平移 / 旋转单位 | mm / 度 | 采集与真机运动接口 |
| 策略输出 | 绝对目标位姿，非增量 | `real_robot_client.py:pop_action` |
| 输入力信号 | 建集可保存审计结果，现行六维策略输入不包含力 | 建集特征与已保存训练配置 |

执行端读取控制器 TCP 状态，按六维顺序打包，模型后处理恢复训练单位。不能在客户端再次进行均值方差归一化，或将绝对目标作为增量相加。

训练数据的 roll 使用连续展开表示；控制器角度可位于 `[-180, 180)`。距离检查通过周期角度差处理物理等价。可选速率限制器将生成的命令角度折返，默认直接目标路径返回原始模型输出，没有统一折返。π0 默认仍直接取上报角度。ACT/SmolVLA 真机入口默认使用 `--roll-reference-deg 180`，将输入 roll 映射到以 180° 为中心的等价分支，匹配当前扫描数据；日志同时保存 `raw_tcp_pose` 与模型输入 `tcp_pose`。该映射不是通用逐回合解卷绕，更换训练角度分支时必须重新核对。

## 2. 图像与特征命名

| 阶段 | RGB | 超声 | 说明 |
|---|---|---|---|
| LeRobot 数据集 | `observation.images.rgb` | `observation.images.ultrasound` | 通常为 3×720×1280 与 3×256×256 |
| π0 策略槽位 | `observation.images.base_0_rgb` | `observation.images.left_wrist_0_rgb` | 训练脚本使用 rename_map |
| π0 真机观测字典 | `base_0_rgb` | `left_wrist_0_rgb` | 默认两路图像在发送侧处理为 224×224 |
| SmolVLA / ACT | 由当前数据集推导特征 | 由当前数据集推导特征 | 不应直接照搬 π0 发送键名 |

轻量客户端与真机入口均支持 `--policy-type pi0/act/smolvla`。ACT/SmolVLA 真机观测字典使用 `rgb`、`ultrasound`，发送尺寸默认分别为 1280×720、256×256；服务端按策略配置形成 CHW 张量并使用 checkpoint 的处理器。回放包保留其相机键；普通回放入口不会自动重命名旧 π0 包，单帧网络校验工具会显式映射这两个键。任务文本通过 `--task` 设置；应记录实际发送内容并核对训练来源。

RealSense 原始彩色格式、OpenCV 通道顺序与模型 RGB 输入之间的转换必须保持一致。超声图像依赖实际采集参数、调色板及重采样方式；同样大小的图像不代表相同的物理成像条件。

## 3. 原始采集与对齐结果

原始 episode 的主要产物为：

```text
episode/
  metadata.json                    采集窗口、示教与采集配置
  robot_records.jsonl              实际状态及主机时间
  robot_actions.jsonl              下发目标、返回码、主机时间
  realsense_frames.jsonl           帧索引、设备与主机时间
  ultrasound_packets.bin          超声原始包
  ultrasound_frames.jsonl         包偏移、设备与主机时间
  ultrasound_metadata.json        超声参数和记录信息
  aligned_samples.jsonl           15 Hz 对齐与质量标记
```

各记录以脚本实际输出字段为准。文件齐全不等于数据有效，还需检查采集窗口、包长度、下发结果、时间偏差及 `quality.valid`。

RealSense 设备钟以毫秒计；超声计数换算依据采集元数据，当前对齐实现使用 200 MHz 时基。跨源对齐使用主机时间映射。控制周期与超时使用单调时钟，避免系统时间调整影响间隔。

跨机器 wall clock 时间差依赖时钟校准，不能未经校准将“接收时间减发送时间”直接作为准确单程延迟；可优先记录同进程测得的 RPC 往返或调用耗时。

## 4. 网络对象与动作块

当前链路通过 gRPC 发送 pickle 序列化对象。轻量客户端用同名模块中的兼容类支持反序列化，所需字段和 `get_timestep()` 等方法都必须一致。`check_stubs_work()` 校验本机对象往返与方法；它不替代真实服务端的兼容测试。

| 内容 | 约定 |
|---|---|
| checkpoint 路径 | 客户端传递的是 GPU 服务端本地路径 |
| 动作类型 | 服务端 `--wire numpy` 供无需 torch 的轻量客户端使用；torch 格式需要接收端支持 |
| 动作长度 | 当前训练 chunk_size=50；请求与模型实际输出需一致 |
| 执行频率 | 15 Hz，完整 50 步约覆盖 3.33 s |
| 时序信息 | 观测与动作附带步号和时间，已执行时间步被过滤 |
| 重叠预测 | `latest_only`，新预测覆盖相同未来步号；不是时间加权集成 |
| 强制观测 | `must_go` 允许绕过服务端观测合理性检查，不是心跳 |
| 压缩默认值 | 回放客户端 none；真机客户端 gzip |

图像预缩决定上行主要体积，`--wire` 只决定下行动作类型。改变图像尺寸时，应同时检查 preprocessing 和推理输出；不能假设两种重采样路径始终数值相同。

## 5. 部署版本的一致性

`pi0_ultrasound_lora/remote/remote_client.py` 是唯一传输层来源。`robot/real_robot/` 下的两个 proto 文件与 `remote/` 内的副本应保持一致；部署时一起复制，避免测试目录与执行目录使用不同版本。

训练和推理需同时保留：底座 revision、checkpoint 配置、adapter（如适用）、pre/post processor 配置与数据归一化信息。LoRA checkpoint 不是独立底座，底座路径失效时不能只移动 adapter 即完成迁移。

接触扫描前还需核对 TCP 偏移、负载、力传感器配置和超声成像参数。当前代码默认阈值见 [执行说明](04-推理与机器人执行.md)，具体场景验证结果记录在开发日志。
