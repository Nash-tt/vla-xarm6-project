# 环境与操作指南

本指南依据 2026-10-13 仓库中的入口参数编写。命令中的 `<repo>`、`<env>`、`<dataset>`、`<checkpoint>` 和设备地址均需替换。示例命令不表示已在目标机器执行验证。

## 1. 环境与资源

| 位置 | 必需资源 | 本仓库提供的内容 |
|---|---|---|
| GPU 机器 | CUDA 可用环境、匹配版本 LeRobot、模型与 tokenizer、LeRobot v3 数据集 | 训练脚本、数据工具、服务端和分析脚本 |
| 工控机采集 | xArm SDK、RealSense 依赖、支持原始包输出的 PhaseLink 程序 | `robot/my_code/` 采集脚本 |
| 轻量回放 | numpy、grpcio、protobuf 和回放包 | `pi0_ultrasound_lora/remote/requirements.txt` 与传输文件 |
| 真机客户端 | 轻量依赖加 OpenCV、RealSense、xArm SDK、超声解码与调色板资源 | `robot/real_robot/real_robot_client.py`、配置副本 |

`robot/real_robot/requirements.txt` 当前只列出轻量传输依赖，不能作为完整硬件环境安装清单。`robot/my_code/requirements_vla_realsense.txt` 列出 numpy、OpenCV 和 RealSense 依赖；厂商 SDK 另行准备。`pi0_ultrasound_lora/env_backup/` 是历史环境快照，不代表可直接重建当前完整环境。

安装依赖时明确解释器，例如 `<env>/bin/python -m pip ...`。核对目标环境再安装，避免将另一框架依赖写入训练环境。项目训练脚本会移除代理变量并设置离线模式，因此模型及相关缓存需提前准备。视频读取使用 PyAV，当前没有修复历史 torchcodec 动态库问题。

## 2. 独立 RGB-D 采集工具

`robot/realsense_collector/` 用于相机检查和独立采集，不控制机械臂，也不包含 PhaseLink。Windows PowerShell 中运行：

```powershell
Set-Location <repo>\robot\realsense_collector
.\setup_windows.ps1
.\.venv\Scripts\python.exe .\collector.py --list-devices
.\.venv\Scripts\python.exe .\collector.py --output .\dataset `
  --instruction "Follow the ultrasound scan trajectory." --duration 20 --no-preview
```

默认 640×480、30 FPS，输出 `metadata.json`、`frames.jsonl`、`summary.json`、`color/` 和 `depth/`。深度 PNG 为 uint16，米制深度通过元数据中的比例恢复。可选 `--action-file` 在每帧读取 JSON 动作文件；它不是三路主线使用的已下发指令日志。相机被占用或 USB 带宽不足时，应先检查其他相机进程、设备枚举和连接条件。

## 3. 三路采集部署检查

采集程序从 xArm SDK 环境导入 `xarm.wrapper`；轨迹主程序还依赖同目录的示教、曲线和 RealSense 模块。部署应复制相关模块，保持 SDK 布局与依赖路径，不宜单独复制一个入口文件。

准备示教点、TCP 偏移、轨迹和超声成像配置后，再使用 `run_fitted_trajectory_vla_sync.py`。它的参数包括 `--robot-ip`、`--output-root`、`--phaselink-exe`、`--ultrasound-ready-timeout`、RealSense 尺寸与帧率等。**该入口会进行真实运动**，不能作为无硬件检查命令运行。采集流程及数据检查见 [采集文档](02-采集与数据处理.md)。

## 4. 无机械臂的网络回放

在 GPU 环境从 LeRobot 数据集导出回放包：

```bash
<env>/bin/python pi0_ultrasound_lora/make_replay_bundle.py \
  --root <dataset> --repo-id <dataset-id> --episode 0 \
  --n-frames 300 --out <bundle.npz>
```

启动服务端，使用适配轻量客户端的 numpy 动作格式：

```bash
LEROBOT_SRC=<lerobot-source>/src <env>/bin/python pi0_ultrasound_lora/serve.py \
  --ckpt <checkpoint> --host 0.0.0.0 --port 8080 --device cuda --fps 15 --wire numpy
```

将回放包及整个 `remote/` 目录复制至测试机器。先用 `--dry-run` 检查包，再建立真实链路：

```bash
python remote_client.py --bundle <bundle.npz> --dry-run
python remote_client.py --bundle <bundle.npz> --server <gpu-host>:8080 \
  --ckpt <checkpoint-on-gpu> --fps 15 --actions-per-chunk 50
```

两端 checkpoint 参数都填 GPU 上的目录；客户端传递的路径决定实际加载。服务端端口监听成功后仍需查看策略加载日志和初始动作结果。记录 RPC 耗时、动作块到达间隔、队列空缺、执行频率及逐维误差。默认控制台混合 MAE 含 mm 与度，不能视为单一物理量，也不能单独作为链路正确性的充分判据。

## 5. 真机部署与影子测试

当前真机入口支持 π0、ACT、SmolVLA，工控机通过轻量协议上传观测，由本机 GPU 推理并返回动作；使用 `--wire numpy` 服务端。模型权重无需复制到工控机。准备部署目录：

```text
<deploy-dir>/
  real_robot_client.py
  run_shadow.ps1
  remote_client.py
  services_pb2.py
  services_pb2_grpc.py
  config/training_ultrasound_metadata.json
  live_ultrasound_current/
```

传输文件来自 `pi0_ultrasound_lora/remote/`，真实设备和解码模块仍依赖 SDK 与 `my_code/`。设置 `XARM_SDK_ROOT` 指向实际 SDK 根目录，并确认超声调色板路径可读取。

在同一个 PowerShell 会话中设置超声原始输出目录并启动 PhaseLink：

```powershell
$env:XARM_SDK_ROOT = "<xArm-SDK>"
$env:PHASELINK_VLA_DIR = "<deploy-dir>\live_ultrasound_current"
New-Item -ItemType Directory -Path $env:PHASELINK_VLA_DIR -Force
& "<PhaseLink-executable>"
```

在厂商程序中连接设备并开始扫描，核对实时目录下的原始包与索引持续增长，确认应用的超声参数与训练版本一致。

只检查配置和依赖：

```powershell
& "<python.exe>" "<deploy-dir>\real_robot_client.py" --validate-only
```

连接实时设备与服务、记录输出的影子测试：

```powershell
& "<python.exe>" "<deploy-dir>\real_robot_client.py" `
  --server <gpu-host>:8080 --robot-ip <robot-ip> `
  --ckpt <checkpoint-on-gpu> --grpc-compression gzip --max-seconds 10
```

检查 `real_runs/` 中观测和动作日志：数据年龄、预测与实际 TCP 的距离、`shadow_valid`、拒绝原因、线程错误及队列状态。影子模式不下发运动指令，不能验证力信号和执行返回码等全部执行条件。

### 5.1 ACT 与 SmolVLA 的 GPU 推理及影子测试

GPU 侧复用 `serve.py`，建议采用独立端口，避免替换现有 π0 服务。`--ckpt` 是启动路径检查，客户端握手中的 checkpoint 路径才决定实际加载；两个模型串行测试，共用一个服务即可。

```bash
<env>/bin/python pi0_ultrasound_lora/serve.py \
  --ckpt <act-checkpoint> --host 0.0.0.0 --port 8081 \
  --device cuda --fps 15 --wire numpy
```

先用真实数据帧核对加载、预处理和输出；工具不连接机械臂，也不构成独立效果评估：

```bash
<env>/bin/python tools/verify_policy_inference.py \
  --policy-type act --ckpt <act-checkpoint> \
  --dataset-root <scan-dataset> --repo-id <dataset-id> \
  --device cuda --output <artifact-dir>/act_inference_check.json
```

SmolVLA 对应替换策略类型与 checkpoint。输出应为 `(1,50,6)`，记录实际设备、输入尺寸、任务文本及耗时；单帧三次推理不能当作稳定性能或任务成功率。

工控机仅部署小型客户端、proto 与解码配置，复用既有 Python/SDK，不安装模型依赖。C 盘空间紧张时，将独立部署目录、日志及临时目录放在 D 盘，不复制已有大型超声包。`run_shadow.ps1` 会将进程 TEMP/TMP 和日志指向部署目录，使用已有 Python，并且只提供影子模式：

```powershell
& "<D-drive-deploy-dir>\run_shadow.ps1" `
  -PolicyType act -Server "<gpu-host>:8081" -RobotIp "<robot-ip>" `
  -Checkpoint "<act-checkpoint-on-gpu>" -PythonExe "<existing-python.exe>" `
  -SdkRoot "<existing-xArm-SDK>" -LiveDir "<existing-live-ultrasound-dir>" `
  -ValidateOnly
```

去掉 `-ValidateOnly` 才连接实时设备开展 10 秒影子测试；切换到 SmolVLA 时替换 `-PolicyType`、`-Checkpoint`，并用 `-Task` 指定经过核对的任务文本。实时超声必须在厂商程序开始扫查后持续更新；旧索引与旧包不能用于实时影子测试。脚本传入 3 秒动作队列空超时，该检查仅在执行模式生效；影子模式按设定时长结束。既有运动保护阈值保持原值。

启动实时客户端前关闭可能占用 RGB 流的 RealSense Viewer 或其他采集程序，保留 PhaseLink 扫查。若相机启动超时，先核对 Windows 设备状态、SDK 枚举与流占用；设备枚举成功不等于客户端已经能读取彩色帧。2026-10-13 首次实时启动超时及诊断见 D-11/P-18；关闭 Viewer 后两个模型均完成实时影子循环，但目标距离检查均未通过，见 D-12/D-13。

ACT/SmolVLA 默认发送 RGB 1280×720、超声 256×256，图像键为 `rgb`、`ultrasound`；输入 roll 默认映射至以 180° 为中心的训练分支。此路径的上传体积高于 π0 双路 224×224，需重新测量延迟。

无实时设备时，可将 `tools/verify_remote_policy.py` 与传输文件放在同一工控机目录，使用既有回放包验证一次观测上传和动作返回。该工具不导入机械臂接口，不下发运动命令；旧 π0 小图包会映射相机键并在服务端重采样，因此该验证不能证明原生图像链路的性能。

```powershell
& "<existing-python.exe>" "<deploy-dir>\verify_remote_policy.py" `
  --server "<gpu-host>:8081" --policy-type act --ckpt "<act-checkpoint-on-gpu>" `
  --bundle "<existing-replay-bundle.npz>" --output "<D-drive-artifact-dir>\act_rpc_check.json"
```

2026-10-13 本机 GPU 与工控机的实际单帧验证见 [D-07 至 D-10](../records/部署实验.md)，实时影子见 D-12/D-13。两个模型的直接目标均超出当前跟踪误差阈值，尚未进行运动测试。核对对应示教起点与传输链路后需重新验证；不得将模型首个预测目标当作自动定位起点。

真实执行需要 `--execute` 与 `--confirm EXECUTE_REAL_XARM_POLICY`，并确保已完成影子测试、起始位姿和设备设置检查。执行程序不会自动移动至起点；每次运动实验应明确时长、参考轨迹、力阈值与停止条件，并记录实际结果。本次文档整理没有执行该步骤。

当前目标与实际 TCP 的位置距离默认阈值为 25 mm。Python 入口可用 `--max-tracking-error-mm` 覆盖；PowerShell 入口使用 `-MaxTrackingErrorMm`，默认也为 25。启动摘要会打印实际位置与角度阈值。相邻命令的位置变化上限仍为 3 mm，姿态跟踪上限仍为 5°；目标距离阈值不等于单步移动幅度。D-12 至 D-17 使用原来的 12 mm，D-18 仅对原始日志做 25 mm 的离线复核，不是新的运动实验。

实际执行入口在使能前检查首个待执行命令，记录 `execute_request` 和 `execute_setup`。目标距当前位置小于 25 mm 仍可能超过 3 mm 单步变化上限而被拒绝。`--max-seconds` 是通过启动检查后控制循环的最长时长，预检失败时不能记录成已经运动；D-19 的 100 秒执行请求在首步 18.01 mm 的检查处退出，实际运动 0 秒。限速执行仍需明确记录原始模型目标与实际命令，不将限速结果当作原始策略动作的直接通过率。

### 5.2 实时 RGB 预览

真机入口增加 `--preview-rgb`，PowerShell 影子入口对应 `-PreviewRgb`。预览直接取现有 RealSense 彩色流，不重复打开设备；关闭 RealSense Viewer 后运行客户端即可。显示的是原生 RGB 相机画面，模型输入仍使用原来的尺寸、预处理和上传流程。

```powershell
# 在原有客户端启动命令末尾增加：
--preview-rgb --preview-fps 10

# 使用 run_shadow.ps1 时，在原有参数末尾增加：
-PreviewRgb
```

OpenCV 窗口由独立显示进程处理，采集端以限频、容量 1、非阻塞队列发送预览帧；显示端落后时丢弃显示帧，不阻塞动作控制。`--preview-fps` 默认 10，只影响显示刷新上限。预览窗口中 RGB 转为 OpenCV 的 BGR 后显示；这一步不改变模型输入像素。

窗口需在工控机已登录的桌面会话打开。普通 SSH 会话中的 GUI 可能无法显示给操作人员；可从工控机本地 PowerShell 启动。关闭窗口或按 Esc/q 请求结束当前测试：等待初始动作及控制循环会检查关闭事件，模型加载等同步调用需返回后才能处理该请求，不能代替实体急停。预览启动失败时测试退出，未启动的相机线程也能安全清理。

2026-10-13 已部署 D 盘客户端并实际完成一次 30 秒带预览的 SmolVLA 影子循环，未发送运动命令；记录见 D-15。测试结束时窗口自动关闭，后续运行需再次带上预览参数。

### 5.3 帧率实验的配置与验收

工控机报告使用本地限速进行真机实验。以下为对应的影子配置示例，需显式指定实际checkpoint；10 mm/s是报告70秒实验值，代码默认平移限速为2 mm/s：

```powershell
& "<python.exe>" "<deploy-dir>\real_robot_client.py" `
  --server <gpu-host>:8080 --robot-ip <robot-ip> `
  --ckpt <checkpoint-on-gpu> --grpc-compression gzip `
  --fps 15 --actions-per-chunk 50 --chunk-size-threshold 0.9 `
  --rate-limited-policy --policy-linear-speed 10 --policy-angular-speed 1 `
  --max-seconds 10
```

执行实验另外按现有确认流程启用执行，并记录实际时长。报告的 `queue-empty-stop=0` 只作为该次条件保留，不作为后续接触实验的推荐停车设置。超声年龄超标时先确认设备实际出包和配置；不能仅为继续运行放宽阈值。

帧率验收同时记录动作数、首末动作时间、最大间隙、超过0.5秒的间隙数、队列深度、RPC长尾和块到达间隔。比较原始目标、限速命令和实际TCP，记录力及图像年龄。独立读取控制器位姿与下发目标的时间可能不同，不能把相邻状态差直接认作同一周期的命令步长。

报告已给出的实验结果及缺失字段见 [部署实验](../records/部署实验.md)。重复测试应保存原始JSONL与统计方法，不能只复制终端平均频率。

## 7. 提交与跨机器协作

### 7.1 工控机读取顺序

先运行 `tailscale status`，确认命令可用、已登录且目标机器在 tailnet 列表中。命令不可用、无法访问守护进程或列表没有目标时，不继续尝试目标 IP 和主机名，改读本机镜像。受限执行环境访问失败不代表 GPU 主机本身没有加入 tailnet。

确认 tailnet 可用后，优先使用目标 Tailscale IP，避免 MagicDNS 配置影响解析。实际连接地址、用户名和密钥路径从本机连接配置读取，不写入仓库。Windows 管理员账户的 OpenSSH 公钥通常配置于 `C:\ProgramData\ssh\administrators_authorized_keys`，需核对实际 sshd 配置。

中文文档通过 PowerShell 读取时，明确 UTF-8；远程复杂命令可使用 UTF-16LE Base64 的 `-EncodedCommand`，输出另设 UTF-8。优先复制文件后在本机读取，避免终端编码造成内容损坏。初次诊断保留 stderr，确认连接成功后再单独处理 CLIXML 输出，避免隐藏真正的连接或文件读取错误。

### 7.2 镜像范围与追溯

GPU 机器上的执行树为 `<training-root>/robot/`，包含 `my_code/`、`real_robot/`、`pi0_remote/`、`realsense_collector/`。`sync.sh` 从工控机读取这些目录，读取远程文件但会覆盖对应本机镜像目录；同步前保留本机未提交修改，同步后比较差异，再按脱敏约定同步到发布仓库并提交。

该脚本**不包含工控机工作区根目录的独立实验总结**，也排除了真机运行产物目录。因此新增总结或实验日志需要另行复制，不能假设更新代码镜像就会取得所有实验依据。

工控机当前没有 Git。镜像抓取和本机提交可以保存抓取时刻的版本差异，但不能恢复两次抓取之间未保存的每次远程编辑。记录时明确远程报告日期、抓取时间、来源文件摘要与对应代码版本。

### 7.3 远程修改前后的版本保留

访问能力取决于当前会话的网络和文件权限；其他助手会话已成功读取或写入，不代表本会话具备相同权限。建立socket前即失败的 `Operation not permitted` 与SSH认证失败不同，应先识别运行环境限制，不重新分发密钥。

执行已授权的远程修改时，先检查采集、控制与推理是否仍在运行，并保存原文件到独立备份或拉回本机；在本机修改验证后传回目标目录，再回读核对SHA-256。结合当时磁盘空间选择备份位置，旧报告中的进程和剩余空间不能作为当前事实。

最后同步镜像、检查差异并提交实际纳入Git管理的仓库，记录来源、时间、文件摘要与变更原因。镜像目录存在不代表它已由Git管理；使用 `git -C <directory> rev-parse --show-toplevel` 确认。相同行数只能作为辅助信息，不能证明两份代码一致。

### 7.4 发布同步

GPU侧仓库通过Git发布版本；当前没有Git的工控机通过已验证的文件传输和镜像流程同步。同步后核对仓库commit、运行目录及文件摘要，特别是传输层与proto文件，不在多个部署目录独立修改同一模块。实际主机路径、设备地址、密钥、数据、权重、厂商文件及原始会话记录不加入仓库。

提交前检查文件列表及差异：

```bash
git diff --cached --name-only
```
