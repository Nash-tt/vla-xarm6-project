# 模型训练与参数设计

核对日期：2026-10-13。实现基线：`e8d95cc`。以下行为依据当前代码；历史实测另行注明。

## 1. 三种训练方案

π0 通过低秩适配器（LoRA）更新部分参数，减少训练显存需求；SmolVLA 使用冻结视觉语言主干、训练动作专家及投影层的方式；ACT 使用新建策略及 ImageNet 预训练 ResNet18 视觉骨干。各模型均输出 50 步动作块。以 15 Hz 执行时，一个完整动作块覆盖约 3.33 s，控制设计必须同时考虑推理延迟与执行期间观测的变化。

π0 的图像键需映射至其底座约定的相机槽位；SmolVLA 的脚本清空预训练特征声明，让数据集推导当前特征；ACT 直接由数据集推导特征。三条训练入口的特征设置不同，不宜互相复制。实际实验配置见 [训练实验记录](../records/训练实验.md)。

## 2. 参数更新范围

**π0。** 采用 PEFT 管理 LoRA。低秩适配器只训练较小的权重更新矩阵，主要挂在动作专家注意力的 `q_proj`、`v_proj`；五个新本体相关投影与时间模块通过 `modules_to_save` 全量训练保存。底座其余参数由 PEFT 冻结。当前脚本设置 r=16、alpha=16，checkpoint 中 dropout=0。实际 target 正则见 [E-01 摘要](../records/training/E-01.json)。

**SmolVLA。** 当前实验 `freeze_vision_encoder=true`、`train_expert_only=true`、`train_state_proj=true`，冻结视觉语言主干，训练动作专家及投影层。日志显示约 450M 总参数、100M 可训练参数。这是未使用 LoRA 的部分参数微调，不能称为全模型更新。

**ACT。** 策略从新配置构建，ResNet18 骨干使用 ImageNet 预训练权重；当前记录约 51.6M 参数均可训练。它以动作序列为输出，通过包含 VAE 分支的训练目标学习示范，因此其 loss 与 VLA 模型 loss 不可直接比较。

## 3. 参数含义与资源取舍

| 参数 | 作用 | 本项目应如何记录 |
|---|---|---|
| batch_size | 每次更新读取的样本数，影响显存与梯度统计 | 记录实际值及梯度累积；不能只抄默认值 |
| steps | 参数更新次数 | 目标步数与完成步数分开 |
| chunk_size | 一次预测的未来动作数 | 与标签时间轴及部署执行范围对应 |
| n_action_steps | 本地策略一次输出后使用的动作步数 | 当前为 50；远程执行还受请求与客户端队列影响 |
| optimizer_lr | 更新步长 | 记录实际优化器及日志末步 lr |
| weight_decay | 优化器正则项 | 依据保存配置记录 |
| warmup / decay | 学习率随步数变化的规则 | 记录调度器与实际总步数 |
| dtype / use_amp | 权重精度与自动混合精度控制 | bf16 不等于 use_amp=true |
| gradient_checkpointing | 重算部分激活以降低训练内存 | 记录显存收益与耗时，不能套用推理结果 |
| num_workers | 数据加载并发度 | 结合 data_s、CPU 和存储观察 |

归一化将输入或标签转换为模型使用的数值范围。当前已保存配置中的 STATE/ACTION 使用均值标准差方式时，周期角度的表示会直接影响尺度，因此展开 roll 与重新统计是配套步骤。padding 到底座所需维数不改变实际控制仍为六维的约定。

## 4. 训练入口与运行

训练环境需已安装对应 LeRobot 版本及 GPU 依赖；`LEROBOT_BIN` 应显式指向正确环境的 `lerobot-train`。模型脚本采用离线模式，底座与 tokenizer 等资源需预先存在缓存或本地路径。

| 入口 | 目的 | 正式运行脚本默认值 |
|---|---|---|
| `pi0_ultrasound_lora/run_train.sh` | 未裁剪数据的 π0 LoRA | 24,500 步，batch 4；历史实际运行有覆盖 |
| `pi0_ultrasound_lora/run_train_scan.sh` | 扫描段 π0 LoRA | 24,500 步，batch 8 |
| `run_train_smolvla_scan.sh` | 短指令版本扫描段 | 20,000 步，batch 32 |
| `run_train_smolvla_pi0scan.sh` | π0 版任务文本对照 | 20,000 步，batch 32 |
| `run_train_act_scan.sh` | ACT 对照 | 20,000 步，batch 24 |

从项目根目录运行，以 SmolVLA 为例：

```bash
LEROBOT_BIN=<env>/bin/lerobot-train WEIGHTS=<smolvla-base> \
DATASET_ROOT=<scan-dataset> SMOKE=1 OUTPUT_DIR=<new-smoke-dir> \
bash run_train_smolvla_scan.sh

LEROBOT_BIN=<env>/bin/lerobot-train WEIGHTS=<smolvla-base> \
DATASET_ROOT=<scan-dataset> OUTPUT_DIR=<new-training-dir> \
bash run_train_smolvla_scan.sh > <training-log> 2>&1
```

π0 对应替换为其入口与底座；ACT 不使用 WEIGHTS，首次运行前需有 torchvision ResNet18 骨干缓存。每轮使用独立输出目录。SMOKE 是流程与资源检查，不是模型效果评估；参数改动后应查看启动配置和首个 checkpoint。

## 5. 训练结果的保存与比较

保存实际启动命令、checkpoint 内 `train_config.json`、底座 revision、数据版本、代码版本和环境。使用 `tools/snapshot_training_record.py` 提取参数及日志证据，填写 [训练记录模板](../records/记录模板.md)。显存需注明 PyTorch 分配峰值、预留内存或整卡采样占用的口径；耗时区分训练环、初始化和恢复后的多段运行。

模型对比使用同一按回合划分的独立评估集，分开报告三维平移和角度误差，并记录任务成功率与成像质量。任务文本对照需先核对数据及归一化等其他因素一致，再分析语言变化的影响。

ACT 的 `temporal_ensemble_coeff` 可启用预测时间集成，且其配置要求 `n_action_steps=1`。当前远程客户端未实现对应逐步推理和集成调度，因此不能只修改训练参数便宣称部署已启用。
